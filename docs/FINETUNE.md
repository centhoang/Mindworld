# Fine-tune plan: a free local coach distilled from Muse Spark (approved by the user 2026-10-28)

## Why this target (decided 2026-10-28)
- The chooser's decisions are already guarded by the memo rules (`allowedMoves`), so tuning only the chooser cannot raise win rate. What stops working after the event is **Teach** (lesson text -> memo rules), which today needs Muse Spark credits.
- So: distill Muse Spark Open's Teach into a small Meta Llama 3.2 (1B for the browser, 3B for power mode) that runs for free, **and** teach the same model the move-voice format. Scored by the existing **Prove** harness (paired seeds), not by vibes. This is the "beyond basic integration" story for Meta tooling (25) and technical depth (20), and it serves the user's goal of free play after the event.
- Llama 3.2 counts as a Meta model (Discord ruling 2026-10-27). Keep Muse Spark Open as the teacher and as the live cloud Cortex during the event.

## Baselines to beat (all in `docs/SPIKES.md`)
- Uncoached held-out win rate 60.5%. Scripted coach 88.0%. Live Muse Spark Open Teach 88.9-89.8% (+28.4..+29.3 pts, ~$0.008, 7-10 s on Baseten; Modal ~2-4 s).
- Untuned Llama: 1B browser valid 90.6% (100% with grammar), sane 40-45%, follows memo 50%; 3B native valid 100%, memo 100/92%, sane 70%. **Step 0 done (docs/SPIKES.md "Fine-tune step 0")**: on the 100 held-out lessons the teacher scores +21.6 pts mean lift (88% valid, 12 cut off by reasoning); untuned Llama with the schema is 100% valid but useless: 3B -3.0 pts, 1B +0.7 pts, ~25% of lessons harmful. Student target: >= +15 pts mean lift on these lessons.

## Pipeline
0. **Baseline (cheap, first):** a `LocalCortex` (implements `Cortex` in `client/src/sim/cortex.ts`) that calls a llama-server (`/v1/chat/completions`, JSON-schema or GBNF grammar for the memo DSL) with the exact Teach prompt. Run Prove on 100 held-out lessons with untuned Llama 3.2 3B and 1B (native, `.scratch/native/bin`). This is the "before" number.
1. **Lessons:** ~3,000 diverse coaching lessons (short natural phrases a player would type: "don't hit it when it's scared", "heal-guard when low", "befriend small ones", plus typos, slang, vague and conflicting ones). Mix of DSL-templated paraphrases and Muse Spark-written variety (~$2). Hold out 300 for eval; never train on them.
2. **Teacher data (rejection sampling):** for each lesson call Muse Spark Open on Modal (`MODAL_BASE_URL`, direct script, **hard cost cap $30 and iteration cap, ledger file, resume**) with the same Teach prompt as the game; keep a memo only if it validates against the DSL (`client/src/sim/memo.ts`) **and** does not lose on the 40 train seeds (same gate as Reflect). Expect to keep roughly 60-80%.
   **Steps 1-2 done (2026-10-28):** `client/src/finetune/gen-lessons.ts` wrote `data/finetune/lessons-{train,val}.jsonl`: 3,197 train + 300 val (1,836 Muse-written in 25 player styles, $0.19; 1,361 templated over the DSL with slang/typo noise); held-out lessons removed by normalized match (test). 25% of lessons are taught on top of an earlier gate-passing teacher memo (`withMemo`). `client/src/finetune/teacher.ts` (direct Modal client `modal-client.ts`: JSONL ledger `.scratch/finetune/ledger.jsonl`, per-kind cap, call limit, resume, retries transient errors) writes `data/finetune/teacher-{train,val}.jsonl`, one row per lesson with memo, train-seed delta vs its start memo and `gate`. **Teacher uses `reasoning_effort: low`**: pilot 40/40 valid, 0 cut off (was 12% at default effort), 80% gate-pass, ~$0.0047 and p50 4.3 s per lesson. **Full run:** train 3,194/3,197 valid (3 not JSON), 2,480 gate-pass (78%), mean train delta +9.8 pts; val 300/300 valid, 218 gate-pass; 0 cut off; teacher $15.83 (ledger total incl. lessons $16.21 of the $30 cap), ~35 min at concurrency 10. Selection is done at training time: keep `ok && gate` rows; lessons that ask for bad play (e.g. "attack every turn") mostly fail the gate, so the student sees few of them; decide in step 4 whether to keep some faithful-but-losing rows so the student still obeys the player.
3. **Voice data:** prompts from `buildVoicePrompt` over random memos/observations from the sim (label = `allowedMoves().moves[0]`, line from the canned bank + ~1,000 Spark-written in-character lines), mixed in at ~25% so one model does both.
   **Step 3 done (2026-10-28):** `client/src/finetune/build-sft.ts` -> `data/finetune/sft-{train,val}.jsonl`. Teach: teacher rows with `ok && gate` that fit `MEMO_JSON_SCHEMA` (all did): 2,480 train / 218 val; target = compact memo JSON in schema key order. **Decision: gate-passing rows only** (maximizes lift, the acceptance metric; faithfulness to bad-play lessons is a known gap). Voice: 827 / 73 (25%), observations sampled from simulated fights under random teacher memos (seeds 50,000+), label `allowedMoves()[0]`, lines from `voice-lines.json` (1,000+ Muse-written lines in 6 situations, $0.15) + canned bank, random pet names.
4. **Train on Modal:** `modal/finetune_llama.py`, base `unsloth/Llama-3.2-{1B,3B}-Instruct` (ungated mirrors of Meta's weights; Meta's own repos are manually gated), LoRA r=16 (or full FT for 1B), chat template, 2-3 epochs, 1x H100 (card is on the workspace; H100 about $3.95/h, expect 10-30 min, <= $6). Volume for outputs; merge LoRA, save fp16, write loss/metrics JSON.
   **Step 4 done (2026-10-28):** `modal/finetune_llama.py` (TRL 0.23 SFT, LoRA r=16 all-linear, loss on the reply only, plain Llama 3 chat template without the date header so training matches llama-server, merge, GGUF f16 -> Q4_K_M with llama.cpp b11934 built in the image). Outputs on Modal volume `llama-coach`: `llama32-3b-e2-r16/` (2 epochs, 10 min train, eval loss 0.41 -> 0.39, 24/24 val Teach replies parse without grammar, GGUF 2.0 GB) and `llama32-1b-e3-r16/` (3 epochs, eval loss 0.47 -> 0.42, GGUF 0.8 GB); each has `merged/` (bf16, for MLC later) and `metrics.json`. Cost about $1.5 of H100 time for both. Local copies: `.scratch/finetune/llama32-{3b,1b}-coach-Q4_K_M.gguf`.
   **Result on the 100 held-out lessons (docs/SPIKES.md):** tuned 3B 100% valid, **+23.8 pts** mean lift, 1 harmful, p50 6.2 s (teacher +21.6, untuned 3B -3.0). Tuned 1B with grammar 100% valid, **+18.4 pts**, 6 harmful, p50 2.6 s (untuned +0.7); without grammar 0% valid (stray `{"` token). Both pass the Teach acceptance (>= 95% valid, >= 70% of the teacher's lift). **Voice** (`client/src/finetune/voice-bench.ts`, 200 sim observations on unseen seeds, sent exactly like power mode): tuned 3B and 1B both 100% valid with and without grammar, 100% of lines 1-8 words (mean ~3.4), p50 0.39 s (3B) / 0.17 s (1B) on the GTX 1050. They pick `allowedMoves()[0]` 100% of the time (that is the training label), so in free-choice turns the tuned voice plays exactly the measured policy.
5. **Convert + serve:** llama.cpp `convert_hf_to_gguf.py` + `llama-quantize` Q4_K_M (local, binaries exist in `.scratch/native/bin`), run in llama-server.
6. **Eval = Prove:** held-out lessons -> student memo (grammar-constrained) -> validity rate -> paired-seed held-out win-rate lift vs uncoached, vs teacher memos, vs untuned Llama. Report in `docs/SPIKES.md`.
   **Step 7, part 1 done (2026-10-28):** the game asks coaches in order Muse Spark (Worker) -> local tuned Llama (when power mode's llama-server answers) -> scripted; a "Free coach" checkbox (shown in power mode) skips the cloud. Verified in the pane with the tuned 3B on 8080 and no Worker: Teach fell back to "Llama coach (local, free)", 3-rule memo, Proof +27.5 pts; with the box checked no `/api/llm` call was made. Power mode runs the tuned model today via `scripts/power-mode.ps1 -ModelPath <gguf>`; a download entry needs the GGUF hosted (Hugging Face, user action). **Hosted (2026-10-28, private for now):** `kysupo/Llama-3.2-{3B,1B}-PetMind-Coach-GGUF` on Hugging Face with model card ("Built with Llama", bench numbers), the Llama 3.2 license and use policy (`licenses/`), uploaded from the Modal volume by `modal/publish_coach.py`. `scripts/power-mode.ps1` now defaults to `-Model coach3b` (pinned size + SHA-256; `coach1b`, `3b`, `1b` also available); the download works once the repos are public (user's call). **Browser 1B (MLC) blocked:** `mlc_llm convert_weight` from the nightly CPU wheels failed four ways on Modal (wrong install flag, missing psutil, NumPy 2 dtype error, then SIGSEGV with numpy<2). Fallback per plan: free coach = power mode only. Next try if time allows: a stable/pinned mlc-llm release or the GPU wheel on a Modal GPU (well-specified Codex task).
7. **Ship (only if accepted):** "Free coach" mode: `LocalCortex` used when the cloud is unavailable/over budget or the player picks local; for the browser, convert the tuned 1B to MLC `q4f32_1` (WebLLM reuses the prebuilt `Llama-3.2-1B-Instruct-q4f32_1_cs1k-webgpu.wasm`, only weights + `mlc-chat-config.json` change) and load it from a public Hugging Face repo via a custom `appConfig.model_list` entry. Hosting needs a **Hugging Face account/token: user action**. Fallback if MLC conversion is brittle: ship GGUF as power mode only.

## Acceptance (decided up front)
- Teach, with grammar-constrained decoding: >= 95% valid memos on 100+ held-out lessons; mean held-out lift >= 70% of the teacher's (teacher ~ +28 pts, so student >= ~+20 pts); win-rate numbers use the same paired seeds and CI as the Muse Spark numbers.
- Voice: 100% valid with grammar, >= 98% without; line <= 8 words.
- If the student misses, report it honestly as a negative result with the numbers; the cloud path is unaffected.
